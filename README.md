SCADA Ignition: Симуляція системи водопостачання

1. Мета проекту
Створити SCADA-систему в Ignition, яка:

        Симулює роботу системи водопостачання з двома hезервуарами, насосами та клапанами. 
        Забезпечує моніторинг рівня води, тиску та стану обладнання.
        Автоматизує керування насосами та клапанами на основі заданих умов.
        Генерує сповіщення про аномалії (наприклад, низький рівень води або високий тиск).
        Архівує дані в базі даних SQL та створює звіти.
        Надає віддалений доступ до системи через веб-інтерфейс.

### Необхідні інструменти
#### Програмне забезпечення:
Демо-версія Ignition (Inductive Automation).
SQLite або MySQL для бази даних (SQLite вбудовано в Ignition для демо-режиму).

#### Навчальні матеріали:
Inductive University (курси: "Ignition Core Certification", "Perspective Module", "Scripting").
Ignition Docs.
Ignition Exchange для прикладів.

### Опис системи
Схема системи
[Джерело води] --> [Насос 1] --> [Резервуар 1] --> [Клапан 1] --> [Резервуар 2] --> [Клапан 2] --> [Споживачі]
                     |                           |                            |
                     v                           v                            v
                 [Датчик тиску]             [Датчик рівня]                [Датчик рівня]

***Примітка***: Система включає два резервуари, два насоси, два клапани, датчики рівня та тиску. Дані симулюються через теги в Ignition.
Компоненти

***Резервуари***:
Резервуар 1: Ємність 1000 літрів, рівень води від 0 до 100%.
Резервуар 2: Ємність 800 літрів, рівень води від 0 до 100%.


***Насоси***:
Насос 1: Наповнює Резервуар 1 від джерела.
Насос 2: Перекачує воду з Резервуара 1 до Резервуара 2.


***Клапани***:
Клапан 1: Регулює потік між Резервуарами 1 та 2.
Клапан 2: Регулює подачу води до споживачів.


***Датчики***:
Датчик рівня в Резервуарі 1 та 2 (0–100%).
Датчик тиску після Насоса 1 (0–10 бар).



### Логіка роботи

Насос 1 вмикається, якщо рівень у Резервуарі 1 < 30%, і вимикається, якщо рівень > 80%.
Насос 2 вмикається, якщо рівень у Резервуарі 2 < 20% і Резервуар 1 > 50%, і вимикається, якщо Резервуар 2 > 70%.
Клапан 1 відкривається, коли Насос 2 увімкнено.
Клапан 2 відкривається за командою оператора або якщо Резервуар 2 > 50%.
Сповіщення:
Низький рівень у Резервуарі 1 (<10%) або Резервуарі 2 (<5%).
Високий тиск після Насоса 1 (>8 бар).
Аварійне відключення насосів, якщо тиск >9 бар.



### Технічні вимоги

Модуль Ignition: Perspective для веб-інтерфейсу.
Теги: Симуляція через Memory Tags або вирази.
База даних: SQLite для архівування даних (налаштування через Ignition Gateway).
Скрипти: Python для логіки керування.
Безпека: Налаштування ролей для операторів та адміністраторів.
Інтерфейс: Адаптивний дизайн для ПК та мобільних пристроїв.

### Покроковий план реалізації
Крок 1: Підготовка

Встановіть демо-версію Ignition (Inductive Automation).
Пройдіть курси на Inductive University: "Perspective Module", "Scripting", "Database Integration".
Створіть новий проект у Ignition Designer, назвавши його "WaterSupplySimulation".

Крок 2: Налаштування тегів

Створіть теги в Ignition:
Рівень води:
Tank1_Level (Float, 0–100, симуляція: 50 + sin(system.date.now()/10000)*20).
Tank2_Level (Float, 0–100, симуляція: 40 + cos(system.date.now()/8000)*15).


Тиск:
Pump1_Pressure (Float, 0–10, симуляція: 5 + random()*2).


Стан обладнання:
Pump1_On (Boolean, False).
 Pump2_On (Boolean, False).
Valve1_Open (Boolean, False).
Valve2_Open (Boolean, False).

Крок 3: Налаштування бази даних

У Ignition Gateway створіть підключення до SQLite (вбудована база).
Налаштуйте Tag Historian для тегів Tank1_Level, Tank2_Level, Pump1_Pressure для архівування даних кожні 10 секунд.
Перевірте, чи дані записуються, виконавши SQL-запит у Gateway.

Крок 4: Розробка HMI

У Perspective створіть сторінку "WaterSupplyDashboard".
Додайте компоненти:
Схема системи: Використовуйте SVG-зображення резервуарів, насосів і клапанів (доступні в Ignition Exchange або намалюйте в Designer).
Індикатори: Цифрові значення для Tank1_Level, Tank2_Level, Pump1_Pressure.
Кнопки: Для ручного ввімкнення/вимкнення Pump1_On, Pump2_On, Valve1_Open, Valve2_Open.
Статус: Кольорові індикатори (зелений для увімкнено, червоний для вимкнено).
Тренди: Графік для Tank1_Level, Tank2_Level, Pump1_Pressure (масштаб: 1 година).


Налаштуйте адаптивний дизайн для мобільних пристроїв.

Крок 5: Логіка керування

Створіть скрипт у Perspective (або Gateway Script) для автоматизації:
# Читання тегів
```
tank1_level = system.tag.readBlocking(["[default]Tank1_Level"])[0].value
tank2_level = system.tag.readBlocking(["[default]Tank2_Level"])[0].value
pressure = system.tag.readBlocking(["[default]Pump1_Pressure"])[0].value
```
# Логіка для Насоса 1
```if tank1_level < 30:
    system.tag.write("[default]Pump1_On", True)
elif tank1_level > 80:
    system.tag.write("[default]Pump1_On", False)
```
# Логіка для Насоса 2 та Клапана 1
```if tank2_level < 20 and tank1_level > 50:
    system.tag.write("[default]Pump2_On", True)
    system.tag.write("[default]Valve1_Open", True)
elif tank2_level > 70:
    system.tag.write("[default]Pump2_On", False)
    system.tag.write("[default]Valve1_Open", False)
```
# Аварійне відключення
```if pressure > 9:
    system.tag.write("[default]Pump1_On", False)
    system.tag.write("[default]Pump2_On", False)
```

Налаштуйте виконання скрипта кожні 5 секунд.

Крок 6: Налаштування сповіщень

Додайте сповіщення для тегів:
```Tank1_Level < 10 ("Критичний рівень у Резервуарі 1").
Tank2_Level < 5 ("Критичний рівень у Резервуарі 2").
Pump1_Pressure > 8 ("Високий тиск").
```

Відобразіть сповіщення в Alarm Status Table на HMI.

Крок 7: Створення звітів

У модулі Reporting створіть шаблон звіту:
Таблиця: Історичні дані Tank1_Level, Tank2_Level, Pump1_Pressure за останню годину.
Графік: Тренди рівнів і тиску.


Налаштуйте автоматичне створення звіту щогодини та збереження у форматі PDF.

Крок 8: Налаштування безпеки

Створіть дві ролі:
Оператор: Доступ лише до перегляду HMI та ручного керування.
Адміністратор: Повний доступ, включаючи редагування скриптів і звітів.


Налаштуйте логін/пароль у Perspective.

Крок 9: Тестування

Запустіть Perspective у браузері.
Перевірте:
Чи коректно відображаються рівні, тиск і стани обладнання?
Чи працює автоматичне керування насосами та клапанами?
Чи спрацьовують сповіщення при аномаліях?
Чи архівуються дані в базу даних?
Чи генеруються звіти?


Спробуйте відкрити HMI на смартфоні, щоб перевірити адаптивність.

Крок 10: Опціональні покращення

Додайте анімацію потоку води на HMI (змінюйте колір труб залежно від стану клапанів).
Інтегруйте SMS-сповіщення через модуль Alarm Notification (потрібна підписка або симуляція).
Створіть дашборд для порівняння ефективності насосів (наприклад, кількість увімкнень за годину).
